## 1. PX4 Autopilot User Guide (https://docs.px4.io/main/en/)

PX4는 드론 및 자율 차량용 오픈소스 자동조종장치입니다. 다기종(멀티로터, 고정익, VTOL, 헬리콥터, 루버 등)을 지원합니다.
본 가이드는 조립, 설정, 비행 운영, 개발 전 과정을 다룹니다.

### 주요 섹션
- **Try PX4**: Docker 또는 .deb 패키지로 시뮬레이션 실행. QGroundControl, MAVSDK, ROS 2와 연결.
- **For Developers**: Development Guide - 개발 환경 설정, 코드 빌드, SITL 시뮬레이션
- **Getting Started**: Basic Concepts - 비행 스택, 비행 모드, 안전 기능, 지원 하드웨어
- **Developer Kits**: 공식 PX4 Developer Kits (Pixhawk 표준 하드웨어, 사전 설치)
- **Configure and Tune**: 센서 캘리브레이션, 비행 모드 설정, 튜닝
- **Hardware**: 드론 부품, 센서, 텔레메트리, RC 시스템, 페이로드
- **Fly**: 안전 기능과 failsafe 동작 확인

## 2. uXRCE-DDS (PX4-ROS 2/DDS Bridge) (https://docs.px4.io/main/en/middleware/uxrce_dds.html)

### 핵심 개요
PX4 v1.14부터 uXRCE-DDS가 Fast-RTPS Bridge를 대체합니다. PX4 v1.13에서 사용된 브릿지에서 마이그레이션하는 경우 migration guidelines를 참조하세요.

PX4는 uXRCE-DDS 미들웨어를 사용하여 uORB 메시지를 ROS 2 주제로 발행/구독할 수 있도록 합니다.
이는 PX4와 ROS 2 간의 빠르고 신뢰할 수 있는 통합을 제공합니다.

### 아키텍처
uXRCE-DDS 미들웨어는 PX4에서 클라이언트와 컴패니언 컴퓨터에서 에이전트로 구성됩니다.
- **클라이언트** (PX4 내장): 정의된 uORB 토픽 집합을 전역 DDS 데이터 공간에 발행/구독
- **에이전트** (컴패니언 컴퓨터): eProsima Micro XRCE-DDS Agent. 클라이언트의 프록시 역할.
  - PX4 또는 ROS 독립적으로 빌드/설치 가능 (버전 호환성만 보장)
  - ROS 2 애플리케이션은 클라이언트 측 코드 의존성 필요 (uORB 메시지 정의 일치)

### 코드 생성
- PX4 빌드 시 uxrce_dds_client 자동 생성 (펌웨어 default 포함)
- 에이전트는 클라이언트 코드 의존성 없음
- ROS 2 애플리케이션은 PX4/px4_msgs 패키지를 워크스페이스에 클론해야 함
- PX4는 빌드 시 PX4/px4_msgs 관련 브랜치로 uORB 메시지 정의 자동 export

### 버전 호환성 (PX4 v1.18 기준)
| ROS 2 배포판 | Fast-DDS 버전 | Micro-XRCE-DDS-Agent | UXRCE_DDS_CLIENT_USE_DDS_V3 |
|---|---|---|---|
| Foxy | 2.0.x | 2.4.2 | 미설정 |
| Humble | 2.6.x | 2.4.2 | 미설정 |
| Jazzy | 2.14.0 | 2.4.3 | 미설정 |
| Kilted | 2.14.4 | 2.4.3 | 미설정 |
| Lyrical | 3.6.x | 3.0.1 | 설정 필요 |
| Rolling | 3.6.x | 3.0.1 | 설정 필요 |

### 에이전트 설치
1. **Standalone (Ubuntu)**: `git clone -b v2.4.3 https://github.com/eProsima/Micro-XRCE-DDS-Agent && cmake .. && make && sudo make install`
2. **ROS 2 워크스페이스 내부 빌드**: `git clone -b v3.0.1` 후 ROS 2 워크스페이스에서 `colcon build`

## 3. Computer Vision (https://docs.px4.io/main/en/computer_vision/)

PX4는 컴패니언 컴퓨터에서 컴퓨터 비전 기술을 주로 사용합니다:

### Pose/Velocity Estimation
- **Optical Flow** (./../sensor/optical_flow): 하향 카메라 + 하향 거리 센서로 2D 속도 추정
- **Motion Capture** (./../computer_vision/motion_capture): 실외를 벗어난 3D pose 추정 (실내 내비게이션 주용)
- **Visual Inertial Odometry (VIO)** (./../computer_vision/visual_inertial_odometry): 온보드 비전 + IMU로 3D pose/속도 추정. 글로벌 위치 정보가 없거나 신뢰할 수 없을 때 사용

### Avoidance/Path Planning
- **Collision Prevention** (./../computer_vision/collision_prevention): RC 차량이 장애물에 충돌하기 전 멈춤 (주로 수동 비행 모드)

### 참고 자료
- PX4 Vision Autonomy Development Kit (./../complete_vehicles_mc/px4_vision_kit) - Holybro 제품
- XTDrone (https://github.com/robin-shaun/XTDrone) - ROS + PX4 v1.9 컴퓨터 비전 시뮬레이션 환경

## 4. PX4 Main Release Notes (https://docs.px4.io/main/en/releases/main.html)

### 주요 변경사항 (Major Changes)
- **Hexarotor 모터 고장 복구**: 단일 모터 고장 시 제어 할당에서 고장난 모터 제거. CA_FAILURE_MODE=1이면 반대 모터 정지, =2이면 역회전 (reverse-capable ESC 필요). CA_REV_THR_FRAC 기본값 0.4. (PR #28078)

### 업그레이드 가이드
- `COM_ARM_TRAFF` → `COM_TRAFF_AVOID`로 대체. 값 3("미션 모드만 적용") → COM_TRAFF_AVOID=2(모든 모드에서 ARM 차단). 수동 ARM 필요 시 COM_TRAFF_AVOID=1(warning only) 설정.
- 6 rotor 모터 고장 처리 재검토: CA_FAILURE_MODE=1이제 hexarotor에서 반대 모터도 정지 (이전에는 고장난 모터만 제거).

### Other Changes
- Fast mission Return modes (RTL_TYPE=2, 4)는 DO_JUMP 명령(루프) 건너뛰기. (PR #26993)

### Safety
- Geofence Aware Return mode (PR #27145, #28001)
- 비상 착륙(Descent mode) 대신 Flight termination 사용 가능
